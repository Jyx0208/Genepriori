# Reproducing published results

The package exposes the full configuration used by every run, so published
tables can be regenerated by pinning data versions. This page lists the
recommended commands and the version-sensitive settings.

## Version pinning

| component | published setup | default |
|---|---|---|
| Open Targets Platform | December 2024 release | current live release |
| STRING | v12.0 | v12.5 |
| Positive threshold | 0.30 | 0.30 |
| Folds | 5, seed 42 | 5, seed 42 |
| Network | PPR, damping 0.85; RWR, restart 0.30 | same |

```bash
genepriori fetch-ppi --string-version 12.0 --min-combined-score 400
genepriori rank --disease <ID> --string-version 12.0
genepriori evaluate --disease <ID> --holdout both --folds 5 --positive-threshold 0.30
```

Every run writes `run_manifest.json` recording the package version, Python,
platform, parameters and data provenance, so a reported number can always be
traced back to its inputs.

## Regenerating the benchmark tables

```bash
genepriori fetch --all
genepriori benchmark --diseases registry --holdout both \
    --variants baseline,ppr,rwr,genetics_ppr,translational_ppr \
    --n-bootstrap 2000 -o results/benchmark
```

`benchmark.csv` is the long-format table (holdout × variant × disease);
`comparison.json` holds paired bootstrap deltas, win rates, sign-test
p-values and BH-adjusted p-values against the baseline.

## Regenerating the debate tables

```bash
genepriori debate --diseases registry --rounds 3 --budget 12 \
    --holdout both --mode heuristic -o results/debate
```

`debate.json` contains, per holdout: the baseline, every decision with its
acceptance reason, the leaderboard, and the best accepted claim with its
intervention.

## Settings that change numbers

When comparing against a published value, check these first:

1. **Data release.** Open Targets scores change between releases, which changes
   positive sets and therefore every metric. The drug datatype is returned as
   `clinical` in current releases and as `known_drug` in older ones; both map
   to the `drug` standard type.
2. **Identifier namespace.** Open Targets now uses MONDO as the primary
   ontology. Older EFO identifiers may not resolve; resolve names with
   `genepriori search-disease` and record the returned ID in the manifest.
3. **Evaluation protocol.** `mask` and `restore` measure different things
   (see `docs/method.md`); compare only within the same protocol.
4. **Gene keys.** Genes are keyed by HGNC symbol, with duplicate symbols
   merged by maximum score.
5. **Network normalization.** Propagation values are min-max normalized before
   blending, so the blend weight has a consistent meaning across algorithms.
6. **Randomness.** Fold assignment, tie-breaking and bootstrap draws are
   seeded and deterministic for a fixed seed.

## Determinism

Re-running the same command against the same cache produces byte-identical
output:

```bash
genepriori rank --disease <ID> -o /tmp/a
genepriori rank --disease <ID> -o /tmp/b
sha256sum /tmp/a/ranked_genes.csv /tmp/b/ranked_genes.csv
```

Deterministic components: alphabetical positive sort → seeded shuffle →
round-robin folds; gene-symbol tie-breaking in rankings, neighbour selection
and top-N cuts; seeded bootstrap.
